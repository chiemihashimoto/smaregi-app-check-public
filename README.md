# スマレジ・アプリマーケット 新着チェック（公開版）

スマレジ・アプリマーケットの公開情報を毎週月曜に自動で確認し、新着アプリと、見つからなくなったアプリの名前を GitHub Pages で公開します。番号・URLや一覧に出ていないアプリは、パスワード付きの Excel にだけ残します。

このリポジトリは **Public** で運用します。社内の事例や成約トークなど、社外に出せない情報は置かないでください。社内向けのツール本体は claude.ai のページで使います。

## 中身

| ファイル | 役割 |
|---|---|
| `index.html` | 公開ページ（新着アプリ・見つからなくなったアプリの名前） |
| `scripts/check_new_apps.py` | 最新リストの更新と新着チェック（Python） |
| `.github/workflows/check-new-apps.yml` | 毎週月曜 9:00（日本時間）にチェックし、ページを公開し直す設定 |
| `data/smaregi_apps.xlsx` | 最新のアプリリスト（有効なリンク／全件チェック結果／見つからなくなったアプリ／更新履歴）。**パスワード付き**で、初回の実行で作られます |
| `data/known-apps.json` | 社内ツールに登録済みのアプリ（ID と名前のみ） |
| `data/new-apps.json` | 公開ページ用の新着の記録（自動で追記） |
| `data/market-ids.json` | 前回の一覧に出たアプリの番号（初回の実行で作られます） |

## 何をどこに載せるか

| 情報 | 公開ページ | Excel | 通知の Issue |
|---|---|---|---|
| 新着アプリ（一覧に掲載あり） | ○ | ○ | ○ |
| 見つからなくなったアプリ（一覧に掲載されていたもの） | アプリ名と日付だけ | ○（「見つからなくなったアプリ」シート） | 件数だけ |
| 見つからなくなったアプリ（一覧に掲載されていなかったもの） | × | ○（同上） | 件数だけ |
| URL は開けるが一覧に出ていないアプリ | × | ○（備考に「一覧に掲載なし」） | 件数だけ |

新着として公開したあとで見つからなくなったアプリは、公開ページから自動で外します。

Public のリポジトリでは、ファイル・Issue・Actions の実行ログを誰でも見られます。そのため Excel はパスワード付きで保存し、公開ページには載せません。Issue とログには、新着アプリだけを名前付きで出し、それ以外は件数だけにします。

## 初回の設定（1回だけ）

1. **新しいリポジトリを Public で作る**
   以前に社内ツール（事例や成約トークの入った `index.html`）を入れたリポジトリは、Public にしないでください。過去の履歴から社内情報が見えてしまいます。必ず新しく作ってください。古いリポジトリは削除して構いません。
2. **ファイルを入れる**
   リポジトリのトップで「Add file」→「Upload files」を選び、解凍したフォルダの中身を、**フォルダごと** ドラッグ＆ドロップして「Commit changes」を押します。ファイルを選ぶ画面から選ぶとフォルダの区切りが外れるので、エクスプローラーや Finder からドラッグしてください。
   入れたあと、トップに `.github`・`data`・`scripts`・`README.md`・`index.html` が並んでいれば正しい状態です。
3. **Excel のパスワードを決めて登録する**
   Settings → Secrets and variables → Actions →「New repository secret」を押し、Name に `EXCEL_PASSWORD`、Secret にパスワード（12文字以上。英数字と記号を混ぜた長いもの）を入れて「Add secret」を押します。
   このパスワードは Excel を開くときに使うので、社内のパスワード管理の仕組みなどに控えておいてください。あとから変えると、前回の Excel が開けなくなり、比較がやり直しになります。
4. **Actions に書き込みを許可する**
   Settings → Actions → General → Workflow permissions で「Read and write permissions」を選んで保存します。
5. **Pages を有効にする**
   Settings → Pages → Build and deployment の Source を「GitHub Actions」にします。
6. **1回手動で動かす**
   Actions タブ →「アプリマーケットの新着チェック」→「Run workflow」（方式は weekly のまま）を押します。
   初回は比較元の Excel がないので、自動で1番から全件を確認します（10〜30分ほど）。アプリ一覧に出ていて社内ツールに未登録のアプリが、新着として出ます。緑になれば成功です。
7. **ページを確認する**
   Settings → Pages の上部に出る URL が公開ページです。通知メールを受け取りたい人は、リポジトリ右上の「Watch」→「All Activity」（または Custom で Issues）を選びます。

## Excel を手元に保存するには

1. リポジトリの `data` → `smaregi_apps.xlsx` を開きます。
2. 右上のダウンロードボタン（Download raw file）を押します。
3. ダウンロードしたファイルを Excel で開き、`EXCEL_PASSWORD` に登録したパスワードを入れます。

毎週の実行のたびに中身が更新されます。過去の版は、ファイルの画面の「History」から取り出せます。

## 毎週の動き（月曜 9:00）

1. 前回の一覧に出た最後の番号から、前後300件を開いて確かめる
2. 前回有効だった URL が、引き続き有効か確かめる
3. アプリ一覧を新しい順に全ページ読み、今回一覧に出た番号も確かめる（番号が大きく飛んだアプリの取りこぼし防止）

増えた・減ったアプリがあると、Excel と公開ページが更新され、Issue でメールが届きます。
社内ツール（claude.ai）への反映は、通知が来たら Claude に「新着を反映して」と依頼してください。

全件（1番から）を確認したいときは、「Run workflow」で方式に `full` を選びます（30分〜1時間）。

## うまくいかないとき

| 症状 | 確認すること |
|---|---|
| Actions が赤くなる | 赤くなっている手順を開き、ログを Claude に見せてください。「Excel のパスワードがありません」と出たら、手順3のシークレットを確認してください |
| `git push` で失敗する | `main` ブランチの保護ルールで、GitHub Actions からの書き込みを許可してください |
| 月曜に動かない | GitHub は、60日間動きのないリポジトリの定期実行を止めます。止まったら Actions タブで有効にし直してください。混雑で数十分遅れることもあります |

## 頻度・範囲を変えるには

- 頻度: `.github/workflows/check-new-apps.yml` の `cron`（日本時間から9時間引いた時刻で書きます）。毎週月曜 9:00 は `'0 0 * * 1'`、毎日 9:00 は `'0 0 * * *'`
- 前後の件数（300件）: `scripts/check_new_apps.py` の `RANGE`
